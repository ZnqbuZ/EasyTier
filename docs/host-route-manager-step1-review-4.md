## U1 — P1：实例停止仍包含关闭整个域的执行能力和释放共享租约

**位置：** 被审文档第 340–366 行；关联第 202、353–358 行。

文档规定一个 RoutingDomain 只有一个协调器。停止流程第 341、362 行却以“本实例”为单位撤销需求，随后第 366 行要求“关停新快照接收通道，取消所有尚未下发到底层的排队任务”，最后释放 ResourceScope 租约。没有把这些动作限定为退出实例独有的资源，也没有区分实例句柄停止与整个域停止。

**反例：** A、B 在同一域运行，A 正常退出。按正文关闭域的接收通道并取消全部队列，B 的后续 DNS/peer 路由变化和既有排队工作也不再推进。若两者共用一个需要独占的资源作用域，A 清理自身资源后释放作用域租约，还可能让另一个进程在 B 继续使用期间接管。

“不删除 B 仍需要的共享路由”只保护了已经安装的对象，不能保证 B 继续接收需求、执行和持有写入资格。

**最小修改要求：** 明确分开两个对外操作，名称可在后续设计中确定：

- **实例停止：** 在协调器内封闭该实例注册/提交入口，撤销其来源；使受这些撤销影响的旧计划失效并重新规划。其他实例的摄取、重试和执行继续运行。只回收该实例退出后已无需求的资源，不能全域取消队列。
- **域停止：** 拒收整个域的新注册/更新，撤销全部实例需求，再全域排空、清理和关闭执行器。
- **租约释放：** 以 ResourceScope 的有效使用者和执行责任为依据；仍有其他实例使用或仍可能有旧副作用时，不因单个实例停止而释放。没有独占租约的共享表模式，同样遵守实例执行隔离规则。

撤销与拒收本实例后续提交需要一个明确的停止边界；不要求此阶段确定锁或队列实现。

**验收：** A 退出时 B 仍可发布并收敛新需求；B 的已排队操作不丢失；共享作用域租约仍被持有；最后一个使用者退出或域停止才执行对应的域级关闭。

## U2 — P1：磁盘不可写时的清理例外会使持久化归属记录过期

**位置：** 第 300–305、312–320 行。

第 300–305 行要求所有需要恢复责任的修改先持久化 Intent，但第 320 行新增“日志完全不可写时，凭内存凭据尽力清理”。这允许在没有持久化 Delete Intent 的情况下修改系统。返回 `CleanupIncomplete(JournalUnavailable)` 仅通知当前调用者，不能让下一进程知道磁盘上的 Created/Committed 凭据已经失效。

**反例：** 持久接口上的 R 已有创建 Commit。磁盘变成只读后，退出流程按内存凭据删除 R，无法记录 Delete Intent；随后进程结束。外部在同一持久接口安装相同属性的 R。重启后日志仍显示旧创建已提交，没有本方删除或未决记录，观察到的属性又完全相同，恢复端可能继续使用过期归属凭据。这里甚至不要求外部与删除并发，正常的先删后建就足够。

第 5.2 节针对 Intent-only 的保守规则不能覆盖此场景，因为持久化历史恰恰没有这个 Delete Intent。

**最小修改要求：** 建议删除第 320 行的无日志路由/规则删除例外：日志不可写时，常规退出也不发起新的显式路由修改；保留未完成责任并如实报告。NIC/宿主会话组件按自身生命周期关闭资源是另一种事件，不能伪装成已经持久化完成的路由清理。

如果坚持保留应急删除，则必须先定义足以让下一进程停止信任旧归属的可靠机制，或严格限制到可证明整体生命周期已终结、不会复用旧凭据的独占作用域；仅有内存证据和当前退出报告不够。本步骤无需引入复杂应急协议，关闭这个例外即可。

**验收：** 创建 Commit 已存在 → 日志不可写 → 请求退出 → 检查没有新增无日志 Delete/Replace；之后恢复不能把未经证明的外部重建对象当成旧资源。

## U3 — P2：Superseded 仅比较 revision，遗漏来源重注册与撤销

**位置：** 第 403–419 行。

提交令牌包含 `source_id + epoch + revision`，且重注册会增加 epoch，但第 419 行把 Superseded **严格限定**为更高 revision。若等待 `(S, epoch=7, rev=100)` 时，S 重新注册为 `(S, epoch=8, rev=1)`，旧提交已经无效，却不满足这个终止条件。显式 Revoked 后也没有规定旧等待者得到什么结果。

**影响：** 已经不可能完成的旧令牌可能一直等到 timeout，调用者无法区分仍在收敛与来源生命周期已结束。这直接属于第二步需要实现的接口行为。

**最小修改要求：** 版本替代判断遵循来源生命周期：同一来源更高 epoch，或同 epoch 更高 revision，使尚未完成的旧提交被替代；来源显式撤销必须给出确定的终止结果（可定义 Revoked/Cancelled，或明确映射到现有结果）。不同来源的更新不影响该令牌；晚到的旧结果不能完成新 epoch 的等待。

**验收：** 等待期间来源从高 rev 的旧 epoch 切换到低 rev 的新 epoch；等待期间来源撤销；无关来源更新不终止等待。
