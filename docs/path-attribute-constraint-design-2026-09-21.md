# 通用路由控制状态机：能力要求与总体设计

日期：2026-09-21。状态：设计草案；当前仓库已有初步属性路由实现，本文描述目标架构。
本文同时适用于独立框架库或框架模块，暂不锁定 crate 划分、公开 API 和声明格式。
目标是构建可嵌入的通用路由控制状态机，作为 EasyTier 底层路由决策的地基。
EasyTier 向它提供连接拓扑、各项 metric、能力和策略；它维护计算状态，输出路由与多路径决策。
DNS、打洞、连接建立、协议同步、实际收发和应用生命周期都由 EasyTier 负责。

## 1. 问题背景：GSO 与 #1871

### 1.1 GSO：从本地开关到可以执行的路径能力

GSO/大包传输暴露的问题是：发送方需要知道某种载荷能否安全经过所选路径，并确保
实际发送遵循这条路径的能力约束。仅检查本地配置、一个邻居，或图上是否存在合格路径，
都不足以回答这个问题。

“全 TCP + 所有节点支持 GSO”可以作为最初验证路径约束的保守用例，但不能直接等同于
最终能力定义。必须区分：

- 本地配置是否请求启用 offload，以及运行时是否启用成功；
- 每条隧道能够承载的消息类型、最大长度和封装开销；
- 中继是否能够透明转发这种载荷；
- 终点能否通过硬件 offload 或软件分段交付。

当前代码已有 GSO 特征宣告、隧道类型属性和约束搜索，但宣告来自配置，TUN 启用仍可能
失败并回退；终点已有软件 TCP 分段。搜索返回下一跳 peer 后，发送层还会独立选择连接。
因此仍缺少“实际能力 → 约束计算 → 具体连接 → 安全交付”的完整契约。

参考：[能力宣告](../easytier-core/src/peers/context.rs)、
[TUN 初始化](../easytier/src/instance/virtual_nic.rs)、
[软件分段](../easytier/src/utils/net.rs)、
[连接选择](../easytier-core/src/peers/conn/peer.rs)。

### 1.2 #1871：可配置入向距离与通用转移代价

[#1871](https://github.com/EasyTier/EasyTier/pull/1871) 允许节点根据邻居的虚拟 IP/CIDR、
安全组、公共节点身份等条件，声明别人进入自己的距离。方向必须明确：

~~~
A 定义针对邻居 B 的入向价格 X
    → A 发布自己的声明
    → 求解器计算 B → A 时采用 X
~~~

它暴露了另一类需求：用户定义规则，规则产生实体属性或转移代价，这些信息按权威来源
传播，参与路径优化，并能解释“谁定的价、哪条规则生效”。

原讨论记录的某版 PR diff 中，proto 增量为 6 行，而传播管线约 130 行、
代价/策略分支约 90 行、规则匹配约 435 行；这些是历史样本，不是当前版本的重新统计。
要消除的是增加属性和策略时反复手写贯穿多个模块的适配，而非仅减少协议字段。

框架的第二个验证用例应是：distance 作为通用属性来源和转移代价规则接入，
无需新增“距离模式”算法分支、专用匹配引擎或专用路由表类型。

## 2. 框架必须支持的功能与前瞻要求

**“必须支持”指架构、数据模型和扩展契约必须容纳这些能力，不要求首期全部实现。**
后续可以扩展计算算法、决策模型及 EasyTier 侧的执行与协议适配，但不能为此推翻
单一来源、统一规则、拓扑身份、时间依赖和路由状态这些基础模型。未实现的能力应明确报告，不得静默降级
为语义不同的行为。

优先级是架构正确性、性能和扩展能力；工作量不作为排除合理架构的主要理由。
兼容性专指**能否与旧版 EasyTier 客户端连接并保持普通互通**，内部 API 兼容不是目标。
旧端兼容不作为限制最优架构的硬约束，但任何破坏点、影响范围和迁移要求必须明确记录。

### 2.1 必须支持的路由计算能力

| 编号 | 框架必须容纳的能力 | 具体含义与设计约束 |
|---|---|---|
| R01 | 属性定义与值的单一来源 | 类型、作用域、单位、缺失语义、来源、传播和操作元数据统一声明；权威值统一更新，协议、计算快照和界面为派生视图 |
| R02 | 有向、多连接拓扑 | 同一对节点的 TCP、UDP、QUIC 等隧道分别有身份、属性和可执行连接；不能把不同连接的优点拼成一条虚构边 |
| R03 | 配置、能力、测量分离 | 配置意图不等于运行时能力；支持时延、丢包、抖动、带宽、MTU、特征、负载和管理距离 |
| R04 | 单路径准入与历史约束 | 支持全路径满足条件、统一类型、计数上限、至少经过一次指定节点/类别、先后顺序、交替及有限历史上下文 |
| R05 | 单目标与多维优化 | 支持跳数、时延、费用、带宽等目标，字典序、加权组合，以及后续 Pareto/资源约束算法；标明算法前提和精确性 |
| R06 | 用户自由定义策略 | 用户组合属性、谓词、阈值、目标和效果；支持参数化策略、IP/端口/协议/安全组分类、路径上下文相关定价，不限于产品内置几个模式 |
| R07 | 随时间变化的决策 | 度量改变可选择不同路径；支持观测窗口、平滑、过期、周期与事件触发、时间规则、迟滞和切换保持时间 |
| R08 | ACL 与 routing 的统一规则机制 | 共用属性访问、谓词、类型检查、规则优先级、效果合并、编译与求值；profile 描述作用域、默认动作、权限和求值位置 |
| R09 | 有语义的候选集合 | 候选保留具体路径/第一条边、度量、约束状态、依赖和有效期；区分精确最优、限定目标的 k-best、Pareto 集和近似候选 |
| R10 | 备份与路径多样性 | 支持 k 短路径、边/节点不相交路径、故障域分离和主备切换；这些要求不是同一个算法问题 |
| R11 | 多路径分流 | 支持 ECMP、加权分流、按流/flowlet/按包粒度、稳定散列、流绑定与有界的本地自适应调度 |
| R12 | 强抗丢包的复制决策 | 计算同一原始包应使用的多个隧道/路径，输出复制位置、数量、去重要求和冗余预算；实际复制与去重由 EasyTier 执行 |
| R13 | 路径集合的可靠性优化 | 考虑共同故障、共享瓶颈、相关丢包、迟到和截止时间；“不同隧道”不自动意味着独立失败 |
| R14 | 实际转发与载荷契约 | 计算结果能绑定具体连接；支持约束逐跳执行或显式路径等后续方式；GSO/MTU/封装要求在失效和回退时仍成立 |
| R15 | 乱序与去重的执行约束 | 计划表达首个有效副本交付、可选有界重排等要求；EasyTier 负责逻辑包身份、去重/重放窗口及加密会话生命周期 |
| R16 | 集合分配与共享资源 | 支持 softmin、容量分配、QoS 预算、预留及后续优化器；同一节点/出口共享容量不能被各条路径独立重复分配 |
| R17 | 来源、信任与多种组合 | 分开表达沿路径折叠、时间统计、多观测者融合；能说明谁测、谁声明、凭什么可信，避免重复样本和陈旧值参与错误合并 |
| R18 | 依赖失效、原子发布与增量计算 | 策略、属性、权限、时间变化按依赖更新；完整快照发布；后续支持局部最短路修复、候选/分配更新和全量回退 |
| R19 | 旧客户端互通边界 | 由 EasyTier 适配握手/同步/数据协议；明确普通互通、新功能限制与破坏点，引擎根据输入能力区分可证明与不可证明的保证 |
| R20 | 可复用、高效且可移植 | 纯计算不依赖 EasyTier peer、网络、操作系统和真实时钟；支持手工拓扑测试；不把每包解释属性袋作为默认执行方式 |
| R21 | 可解释与可验证 | 能解释属性来源、命中规则、算法、候选淘汰、切换原因、计划版本和失效原因；验证计算结果与实际执行一致 |
| R22 | 生成式配置与适配元数据 | 单一声明驱动可生成的路由配置/API/CLI/UI 部分；可描述 Never/Full/Digest 等传播意图，具体同步和按需获取由 EasyTier 完成 |
| R23 | 持续演化的路由状态机 | 接收拓扑/metric/策略变更和显式时间输入，维护历史、依赖、候选与当前决策，输出结果快照或差量；支持重放验证及后续增量计算 |

R09–R16 中的高级候选、分流、复制、去重和资源分配是明确的后续扩展要求，
不代表现在实现这些功能；具体边身份、结果模型和载荷契约则属于首期基础。
R07/R17/R18 的时间、来源与版本契约要先确定，复杂统计、融合算法与增量算法可以后补。
首期范围见 §10。

### 2.2 系统边界：嵌入 EasyTier 的计算附件

这里的“状态机”是持续接收输入、维护路由计算状态并产生决策的库/模块。
它可以保存经过归一化的拓扑副本、观测窗口、已编译策略、历史选择和增量索引，
但不负责获取连接、主动测量网络或执行结果。

| EasyTier 提供的输入 | 状态机负责的计算 | 输出给 EasyTier |
|---|---|---|
| 已知连接拓扑、连接身份与能力 | 准入过滤、约束搜索、路径度量与择优 | 下一跳/具体连接引用、路径、可达性与载荷要求 |
| 时延、丢包、带宽、负载、共享瓶颈等 metric | 时间统计、候选比较、集合优化与稳定性决策 | 多路径集合、权重、复制建议、主备和切换条件 |
| 用户策略、可信身份/组属性、可选流量上下文 | 统一规则求值、分类、上下文代价与查询计算 | 准入/标记/选择结果、匹配原因与诊断 |
| 拓扑差量、观测变更、显式时间推进 | 依赖失效、重算或增量更新 | 结果快照/差量、失效通知、下次需要推进的时间 |

EasyTier 负责 DNS、打洞、连接建立、握手、协议传播、凭据验证、加密、包解析、
实际发送/复制/去重、系统资源和应用生命周期。这些功能可以使用路由结果，
但不迁入状态机，也不作为状态机的领域模块重新实现。

“支持 EasyTier 的底层网络路由”指其路由判断、路径选择及多路径控制可建立在这套
通用计算机制上；不要求 EasyTier 的所有产品功能都由本系统托管。
本文件中关于发送、去重和旧协议的说明，定义的是宿主接入契约与可行性要求。

## 3. 由上述要求推导出的基本约束

1. **编译规则不冻结输入。** 缓存策略程序，依据不断变化的观测重新计算结果。
2. **属性只被声明一次，但可以有多个派生表示。** 单一来源不要求协议与计算共用内存布局。
3. **统一规则引擎。** ACL、routing、分类和发送策略共享规则语义；已有上下文可以提前求值。
4. **约束必须参与搜索。** 不能先求无约束最优路径，再检查它是否满足约束。
5. **策略自由度不等于任意目标都能常数时间查表。** 搜索/缓存必须绑定目标、约束和影响结果的参数。
6. **结果必须说明保证范围。** 达到状态、标签、时间或内存预算时，不得把截断结果冒充完整答案。
7. **路径计算与发送执行有共同契约。** 存在合格路径不能代替当前计划实际使用合格路径。
8. **安全准入与软偏好分开。** 禁止不能编码成一个“足够大的”费用；配置的回退也不能悄悄违反硬约束。
9. **普通互通与新增功能保证分别验证。** 旧节点未知能力不能被推定为支持；内部 API 可改变。
10. **后续扩展不必首期实现，但必须有验收用例和归属。** 不以加一个无语义的插件槽代替设计。
11. **状态机有记忆，但不接管网络 I/O。** 拓扑、观测历史、当前决策和增量索引属于计算状态；外部事件和时间由 EasyTier 注入。
12. **统一机制不强制统一算法。** 图搜索、规则匹配、时间统计和集合优化共用属性、依赖与结果契约，各自使用适合的算法。
13. **计算建议不等于已经执行。** 输出连接引用和计划后，由 EasyTier 验证并执行；执行侧变化作为新输入影响后续决策。

## 4. 总体方案：输入驱动的通用路由状态机

### 4.1 组成与数据流

系统以库/模块形式嵌入 EasyTier。EasyTier 把已经获得的连接拓扑、metric、能力、
策略和变更输入状态机；状态机更新内部计算状态，输出可被 EasyTier 消费的决策。
不需要独立服务、应用运行时、socket 工厂或协议状态机。

~~~mermaid
flowchart TD
    A["EasyTier：连接拓扑 / metric / 能力 / 用户策略"] --> B["输入快照或变更批次"]
    T["EasyTier：时间推进 / 可选流量上下文"] --> B
    B --> C["路由状态：输入视图、历史、程序、依赖"]
    C --> D["规则求值 / 路径搜索 / 候选与集合优化"]
    D --> E["新状态与路由决策：快照 / 差量"]
    E --> F["EasyTier：消费结果并实际转发"]
    F --> G["EasyTier：新的测量与执行反馈"]
    G --> B
~~~

| 内容 | 路由状态机 | EasyTier |
|---|---|---|
| 拓扑与属性 | 保存/索引输入视图，检查计算所需的身份、版本和类型 | 发现与建立连接，维护真实连接，获取和同步属性 |
| 测量与时间 | 根据输入做窗口统计、过期、稳定性和依赖计算 | 主动测量，提供原始样本或已聚合 metric，驱动定时调用 |
| 规则与搜索 | 编译、求值、约束、目标、候选、分配和结果解释 | 提供策略、身份/权限投影及查询上下文 |
| 状态与更新 | 管理计算状态、缓存、结果版本与增量索引 | 决定调用线程、事件批次、计算调度和结果接入 |
| 实际执行 | 输出具体边/连接引用与决策契约 | 解析真实句柄，检查存活/能力，收发、复制、去重、加密和系统操作 |
| 协议与上层功能 | 接收解码、验证后的计算输入 | 负责旧端互通、路由同步、DNS、打洞及全部上层功能 |

共享规则核心可以供 ACL 和流量分类调用：EasyTier 提供已经提取的属性上下文，
状态机返回判定。它不因此拥有包解析、收包循环或完整数据面。

### 4.2 状态、输入与输出

状态机的逻辑形状是：

~~~
(State[t+1], Output[t]) = advance(State[t], InputBatch[t], Now[t])

lookup(ResultSnapshot, Query, Context) -> Decision
~~~

这不要求每步物理复制完整 State；实现可以原地更新、共享不可变数据或保留增量索引。
advance 描述确定的状态转移，lookup 是读取已计算结果或执行有界规则求值。

| 对象 | 至少包含/表达 |
|---|---|
| State | 拓扑与属性视图、观测历史、已编译策略、查询绑定、当前候选/计划、保持状态、依赖和版本 |
| InputBatch | 初始快照或拓扑/metric/策略差量、来源代次与版本、可选执行反馈或查询注册 |
| Now | EasyTier 提供的逻辑/单调时间，用于观测过期与保持期；日历时间规则另由显式墙钟/时区上下文驱动 |
| Output | 新结果快照或差量、不可达/失效/拒绝原因、结果版本与有效期、下一次需要推进的时间 |
| Decision | 准入、下一跳/路径、多连接集合、权重、复制/主备方式、载荷要求和解释 |

同一输入序列与初态应可重放得到一致结果；随机化的计算如果需要，也应显式输入种子或
随机状态。源记录版本用于拒绝重复/过时变更，计算 generation 标识本地产物，
两者不能混用。批次处理和读取的可见性要有明确契约。

非法批次应返回诊断且不发布半更新的结果；连接撤销等硬失效不能等待软指标的
平滑或保持期。lookup 必须能区分有效决策、过期/失效、尚未计算和不可满足，
不能让旧快照的存在被误解成当前连接仍可执行。涉及有效期的读取使用宿主提供的时间。

状态机只在收到调用时推进，不自己等待真实时钟或启动探测。它可以返回 next_due，
由 EasyTier 在到期时再次调用。未来若计算需要分步、取消或后台执行，使用明确的
计算任务与输入代次契约接入；不因此演变成应用资源管理系统。

### 4.3 “路由状态机”与“路径约束自动机”是两层概念

路由状态机处理网络随时间变化：记住旧 metric、旧路径、迟滞状态、依赖和计算结果。
它的完整状态不受“最多 64 个自动机状态”之类限制。

路径约束自动机是内部某种搜索算法的工具，用来记住一条候选路径是否经过指定节点、
协议顺序是否满足等。它的状态预算只限制相应查询的搜索空间，见 §6.3。

例如，同一规则在不同时间选择不同路径：

~~~
输入：A→B 与 A→C 的拓扑，策略为满足能力后时延优先
输入：metric 第 1 版，B 路径较优
输出：选择 B

输入：metric 第 2 版，C 路径较优
计算：结合最新输入以及策略指定的平滑/保持状态
输出：选择 C，或继续保持 B 并说明切换条件

输入：B 连接撤销
输出：相关计划失效，给出满足契约的其他选择或不可达
~~~

复制抗丢包也是计算结果的一种：状态机可以输出“使用边 e1、e2 各一份”，
EasyTier 执行复制、维护逻辑包身份并接收去重。状态机不接管两条隧道。

### 4.4 内部计算分解与性能

内部可以按需要组织以下操作，不要求固定 crate 划分：

~~~
compile(schema, rules, profile) -> Program
evaluate(program, context) -> DecisionFields
solve(snapshot, program, query, budget) -> SolveResult
allocate(candidates, resources, program, context) -> DeliveryPlan
~~~

- Program 缓存规则结构，metric 变化仍会更新计算结果。
- QueryKey 绑定真正影响答案的约束、目标和参数；RouteClassId 只是内部索引。
- SolveResult 记录候选、精确性与输入版本；DeliveryPlan 描述交给 EasyTier 的发送决策。
- State 可以保留上一轮搜索/分配结果，以支持后续增量修复、依赖失效和切换稳定性。
- 属性声明、规则和算法扩展保持通用；默认使用强类型访问、紧凑状态与稠密索引。
- 不要求每包经过 advance，也不要求每包更新全局观测。EasyTier 可持有结果快照，
  快速 lookup 或执行编译后的有界分类规则。
- 高频本地调度若需要查询状态机，使用小上下文和轻量决策接口；完整图搜索不隐含在每包 lookup 中。

纯函数 solve 仍适合作为内部算法和正确性基准，但对外的系统抽象应是有记忆、能更新、
能持续输出结果的路由控制状态机。持有计算状态与执行网络副作用是不同的职责。

## 5. 属性、实体与单一来源

### 5.1 单一声明，多个派生视图

属性声明统一描述身份、类型、单位、实体/上下文作用域、缺失语义、权威来源、
可用操作、传播方式以及可生成的展示/配置元数据。

配置、运行时能力、测量和派生值是不同语义的属性，不强行一一对应。例如：

~~~
请求启用 GSO → 平台初始化与协商 → 实际能力 → 对外宣告 / 路由输入
~~~

同一个权威值可以生成协议消息、强类型宿主结构、计算快照和紧凑数组；
不得依赖用户代码在多处手工同步更新。派生值应能追溯输入版本。

声明入口可以是带注解的 Rust 类型、proto descriptor 或独立 schema。
选型标准是能否统一生成类型、访问器、映射、校验与元数据，而不是必须使用 proto。
若用 proto，属性身份至少包含消息/schema 身份和字段 tag；tag 仅在消息内唯一。
稠密计算槽位是生成的布局信息，不是第二份属性语义来源。

在已有操作语义范围内，新增属性应接近“一处声明 + 一个取值来源”。
新增此前没有的统计方法、路径代数或物理执行动作，仍需实现、注册与验证。
领域 UI 和配置推导也不都能从字段类型自动生成。

### 5.2 实体、方向与连接身份

- Node：节点的能力、身份与节点属性。
- Tunnel/Adjacency：节点间可单独选择的有向连接，携带类型、度量和载荷能力。
- Path：具体边序列及其派生状态、度量、依赖。
- Resource/FailureDomain 引用：描述共享出口、容量和共同故障关系，服务于集合优化。
- Flow/Packet/Query：规则求值上下文，不需要作为全网拓扑实体广播。

AdjacencyId 至少能区分所有者、实例代次和本地连接身份。同一对 peer 可以有多条边，
不能用 A.tunnels[B] 的单值覆盖它们。重连后的新连接不能自动继承旧计划的全部保证。

不强制引入 Channel。传输层内部透明的 MPTCP 子流、bond 成员等，由传输实现报告
有效能力；框架直接控制的多条隧道则分别建边。有效属性的定义必须说明统计和承载语义。

当前 RelayPeerMap 主要管理端到端会话，发送仍依赖下一跳路由；不能直接把它当成
独立物理边反馈给同一个路由计算。虚拟链路若进入图，必须声明底层依赖与封装契约，
防止递归、自引用和能力误判。

### 5.3 谁写、谁测与如何组合

观测者测量某条有向连接；被描述者声明自己的能力、入向价格或中继资格。
#1871 可以先由 A 将针对 B 的规则求值为声明，再由快照构建阶段将其关联到 B → A；
时延不能因为方向相反就自动使用同一含义的值，RTT 与单向时延也应区分。

每份原始记录按来源单写。多来源估计若融合成一个值，融合规则是另一项派生计算。
统一属性核心可以支持三类操作，但它们必须有不同的输入语义：

| 操作 | 输入 | 输出 |
|---|---|---|
| 路径折叠 | 有序的节点/边观测与路径状态 | 路径度量、约束状态 |
| 时间统计 | 同一来源随时间变化的样本 | 平滑值、分位数、置信度、过期状态 |
| 观测融合 | 多来源的有身份样本 | 明确融合规则下的派生估计 |

平均值也需要考虑重复样本、窗口和过期；不能假设只有 LWW 才需要来源和版本。
P95 之类统计不能仅凭每条边的一个标量直接推出整条路径的 P95。

属性未知用显式 presence 表达。规则使用声明的缺失语义；硬约束只接受明确成立的判断，
对未知值取反不能获得许可。未参与当前策略的未知属性不影响该策略。
普通选路的未知度量可以按策略使用带标识的估计或默认值。

## 6. 自由策略、统一求值与路径算法

### 6.1 用户定义规则，系统编译实际程序

规则的基本形状是“谓词 → 效果槽”。谓词可以读取节点、隧道、路径状态、流量、
查询参数和时间上下文，使用类型允许的比较、集合、前缀与布尔运算。

用户可组合属性、阈值、路径要求和目标，不限于 least-hop / latency-first 等预置模式。
内部 RouteClassId 只是已编译查询的索引；规则数量、流量数量和不同查询的数量并不相同。
编译不能通过枚举所有 IP、flow 或未来所有参数值实现。

例如“时延 + α × 管理费用”允许参数 α 改变。改变后若最优路径可能不同，就需要
重新计算、命中对应缓存，或由专门算法提供参数范围内的结果。缓存的是程序及其
有效结果，不是将所有动态属性变成常数。

效果槽按运行时能力注册并类型化，至少为以下类别留出语义位置：

| 效果 | 示例 | 合并语义要求 |
|---|---|---|
| admit | ACL 允许/拒绝、边准入 | profile 声明首条命中、优先级、默认动作 |
| cost/select | 入向代价、优化目标 | 区分累加、覆盖和目标优先级，定义非负/有界等契约 |
| annotate | exit-node、流量类、DSCP | 明确作用对象、命名空间和覆盖次序 |
| delivery/allocation | 单发、分流、复制、主备、资源预算 | 明确组合是否合法，不能把复制误当权重归一化 |

新增物理执行语义仍需 EasyTier 侧执行器支持；不能声称任何未来动作都能仅通过新属性实现。

### 6.2 ACL 与 routing 共用一个规则核心

统一属性读取、谓词、类型系统、规则优先级、效果合并、编译和求值。
Profile 限定可读上下文、可写效果、默认动作、求值点和权限；限制错误作用域，
但不声称能消除共享实现、错误配置或上下文提供者带来的全部风险。

“专门化”指同一编译器根据已知上下文进行部分求值与布局优化，不要求建立两套后端。
例如“TCP 流量不得经过 UDP 隧道”，在计算 TCP 路径时可以只剩 UDP 边过滤。
包级规则可以使用预解析的前缀/集合结构和直接字段访问，避免每包解释属性字典。

Routing 的图搜索、ACL 的收包/发包/转发求值、QoS 标记和发送调度，使用共同规则语义。
包解析、组身份认证、系统队列与实际发送由宿主提供。
QoS 中的标记和选择可由规则表达，带宽预留还需要资源分配及宿主执行器。

### 6.3 根据语义选择求解方法

| 需求 | 求解方式与契约 |
|---|---|
| 全 TCP、每节点支持某能力、每边 MTU 达阈值 | 过滤图后搜索；源节点、目标节点和中继的条件按策略角色检查 |
| 非负加性标量或加性向量字典序 | 单标签 Dijkstra；单位元、扩展和排序满足算法要求 |
| 必经类别、顺序、交替、有限历史、上下文相关代价 | 按策略构造有界自动机，在节点 × 状态上搜索 |
| Pareto、多资源约束、不能安全单标签剪枝的组合 | 专门求解器/多标签搜索，报告复杂度与精确性 |
| k 简单路径、不相交路径、故障域组合 | 各自的候选或集合算法，不由通用单标签搜索自动获得 |

自动机状态必须保留当前策略继续搜索所需的充分信息，包括代价函数读取的历史。
转移读取边与相关节点属性，初态处理源节点。只对无法到达接受状态的死状态剪枝，
不能把“尚未满足”当成“以后不可能满足”。

自动机按实际策略编译、最小化和组合。预算在编译/求解接口中显式表达；
不将旧实现的 64 固定为所有未来策略的语义上限，更不能达到上限后静默丢状态。

“比较结果是全序”不足以保证单标签搜索正确。共同延伸不能颠倒用于剪枝的路径优劣，
后续可行性也必须由保留状态决定。例如先比较最大瓶颈带宽、再比较最小时延：

~~~
前缀 P = (带宽 10, 时延 100)，Q = (带宽 9, 时延 1)，P 更优
共同接一条 (带宽 1, 时延 1) 的边
结果 P = (1, 101)，Q = (1, 2)，Q 更优
~~~

所以开放的 fold/cmp 扩展需要算法契约；不能仅凭闭包签名或操作名字证明单调性。
首期支持可验证的常见操作，其他操作通过合适后端扩展，未支持时明确报错。
目标也不能用不安全的强制类型转换、NaN 或溢出来绕过代价契约。

自动机乘积图求得的最短游走可能重复物理节点，即使边权为正。
是否要求物理简单路径、是否允许服务链绕行、最大跳数多少，必须明确；
暴力枚举简单路径不是所有自动机策略的正确性 oracle。

### 6.4 候选不是任意未来查询的完整索引

每个候选集必须记录生成它的目标、约束、参数、快照以及完整性。
“当前目标的前 k 条”不能保证包含另一个目标的最优解；
完整 Pareto 前沿也有适用目标范围和潜在的大规模成本。

表结构统一表示目的/查询对应的结果，可共享图、程序、候选与发送动作；
允许对不同查询分别求解，不手写不同模式的专用表类型。
单路径首期可以只有一个候选，但结果类型不能把“只有一个赢家”固化成唯一表达能力。

ECMP 可来自等价最短路径关系，不必等待通用 k-best。
第 2 短路径可以是某些故障的备用，但不保证故障隔离；边、节点不相交和共享故障域
需要明确约束。重构路径时保留边身份，不能只记节点序列。

## 7. 动态观测、时间与计算生命周期

### 7.1 编译、重算与执行的不同频率

| 触发 | 应做的工作 |
|---|---|
| 属性/规则定义变化 | 更新相关编译结果和依赖 |
| 时延、丢包、负载等观测变化 | 更新事实，重新计算受影响的候选、排序或分配 |
| 时间窗口边界、观测过期 | 即使没有网络事件也重新求值 |
| 连接死亡、能力撤销 | 立即使相关发送动作失效，按契约处理回退 |
| 每包本地队列/可写状态变化 | 在计划授权范围内执行有界的轻量调度 |

Observation 至少能表达来源、被观测对象、值、来源代次/版本、采样时间或年龄、
接收时间及有效期；统计窗口和置信度按属性语义扩展。
本地调度用单调时钟；远端时间不默认与本地同步，进程 Instant 不直接上线。
权威来源版本和本地计算 generation 是两类版本，不能混用。

全量最短路的数学对象是一份确定快照，不表示真实网络在整个路径传播期间恒定。
冻结计算输入只是保证结果可复现；输入变化通过失效与新计划体现。

### 7.2 稳定性、反馈与测量定义

平滑、迟滞、切换阈值、最短保持时间、按流绑定和 flowlet 切换是显式策略或执行参数。
不能一边承诺“始终使用当前估计最优”，一边隐藏保持旧路径的逻辑。

负载感知和冗余发送会改变被测网络：分配影响负载，负载又影响下一轮分配。
需要有限的更新频率、资源预算和稳定性验证；实际网络反馈不能在一次纯函数求解中
被假定为已经收敛。备用路径需主动探测或有可解释的陈旧处理。

区分探测 RTT、业务单向延迟、隧道交付失败、重传和截止时间内未到达。
TCP 等可靠传输的底层丢包可能表现为迟到与队头阻塞。
多路径需要保留各路径的观测和整体交付结果，不能去重后只看见“都成功了”。

### 7.3 发布、依赖与增量扩展

计算捕获一致的拓扑、观测、策略、权限视图及其版本，在锁外运行。
宿主合并更新、取消过时任务，确保旧结果不覆盖更新结果。
FIB、相关目的地址解析和连接动作以完整的不可变快照发布，读者只使用一代视图。

依赖描述必须足以响应可能改善结果的变化，不能只登记当前赢家用到的边；
未选中的边降价、新连接加入，也可能改变最优解。
增量后端可以保留最短路径树/关系、距离和反向依赖，局部修复或全量回退。
不能延续“未更新条目的版本低于整表水位就不可达”的语义。

本地原子发布只解决本地一致性。分布式节点的快照不一致仍可能产生短暂环路；
严格路径执行与普通逐跳模式分别定义收敛和故障行为。
参见 [RFC 5715](https://www.rfc-editor.org/info/rfc5715/)。

## 8. 发送计划、多路径与强抗丢包扩展

本节的计划计算属于状态机，发送、复制、去重与加密等执行属于 EasyTier。
执行侧约束用来确定结果模型必须表达什么，不要求把执行器实现搬入框架。

### 8.1 从路径结果到可执行计划

计划至少表达查询身份、版本、路径/连接引用、动作语义、载荷契约、依赖与失效规则。
PayloadContract 描述消息类型、最大长度、封装和分段要求；候选参与同一发送动作时，
必须满足该动作的载荷要求，不能任意混合后仍宣称原有保证。

| 模式 | 一个原始包的执行含义 |
|---|---|
| Single | 使用一个合格路径/连接 |
| Select/Split | 在合格集合中选择一个，按权重、流散列或轻量调度执行 |
| Replicate | 选中的多条路径各发一份，接收去重 |
| Primary/Backup | 正常使用主路径，按规定失效条件切换 |

这些是目标语义，不要求首期实现所有执行器。权重可以是候选/分配结果的属性，
但选择次数、复制位置、粒度、去重域和失败行为是计划级语义，不能只用一个权重表示。

分配器对整个集合求值，可后续支持 softmin、water-filling、优化模型和 QoS 预算。
单链路带宽估计和节点/出口共享资源预算分别建模。路径瓶颈可以提供容量上界，
但不能代替多条流/路径竞争同一资源时的联合分配，也不能保证实际吞吐。

### 8.2 转发必须落实计算约束

本地多隧道发包绑定具体连接身份；不能查到下一跳 peer 后交给默认连接选择器重新决定。
连接重建或能力变化要验证计划契约，失败后只能在允许集合内切换，或使用明确授权的降级。

普通、具有一致后缀语义的策略可以采用逐跳 class 转发。
历史/顺序约束、源端特有目标或严格路径固定，需要携带必要状态并配套求解，
或者采用显式边路径、分段指令、已安装标签等执行方式。框架应容纳这些方式，
首期不必定下完整的新包头或安装协议。

线上策略身份要有共同语义和版本，不能直接传各节点自行分配的本地索引。
中继不能任意重置约束、预算或切换到另一目标。
显式路径与候选/流量导入可参考
[RFC 9256](https://www.rfc-editor.org/rfc/rfc9256.html)，不要求直接实现 SR 协议。

### 8.3 复制抗丢包与相关失败

用户可以定义“不同隧道同时发送”“优先不同中继/出口”“在冗余预算内尽量降低丢失”。
同一对 peer 的不同连接可以先满足本地复制场景；全网路径冗余还需控制后续的汇聚。

集合目标应考虑共同失败，而非仅取单路径指标最好的前两名。
若两条路径丢包事件独立，丢包率 p1、p2 的双副本共同丢失概率才是 p1 × p2。
共用上行、路由器、中继或运营商瓶颈时，不能假定独立。
对实时流量还可优化“所有副本都未在截止时间 D 前到达”的概率。

计划应声明复制次数、复制节点/位置、资源预算、队列积压与迟到处理。
源端已经复制的包不能在每个中继重新复制，形成逐跳倍增。
复制增加网络负载，因此自适应策略不能无界地以更多副本应对拥塞。

框架提供候选关系、资源约束和计划表达；联合失败估计与具体优化器可后续扩展，
复制执行器则由 EasyTier 后续实现。
参考 [RFC 8655 的复制与消除机制](https://www.rfc-editor.org/info/rfc8655/)。

### 8.4 去重、乱序和安全会话

一个逻辑包的身份应独立于所选连接，例如发送方、会话代次、序号空间和包序号。
多个副本共享这个身份；换路径/计划不应自动重置去重域。
默认可采用首个有效副本立即交付、其余副本丢弃；是否恢复包间顺序是独立选项，
需要有界缓冲、等待上限和迟到语义。去重不等于有序，
参见 [RFC 9550](https://www.rfc-editor.org/info/rfc9550/)。

去重身份应受到认证保护，状态更新不能被无效包污染。
逻辑去重序号不默认等于连接加密 nonce；不同连接/会话的副本仍需被识别为同一逻辑包。
允许共享不可变载荷以减少复制，但修改包头、加密和连接封装必须遵守各自的内存与 nonce 契约。

去重与加密重放窗口都要覆盖允许的路径时延差和发送速率，并有明确内存上限。
当前 SecureDatagramSession 使用 256 包重放窗口：同一序号空间每秒 10,000 包、
路径相差 50 ms 时约有 500 包跨度，慢路补救包可能已落在窗口外。
这是后续复制功能必须解决的具体约束，不要求首期实现新窗口。

## 9. 旧客户端互通与协议演进

本节的兼容性只讨论新旧客户端能否连接、交换普通路由并正常收发普通业务。
Rust API、内部模型和管理 API 可以重新设计；旧平局结果与旧字段布局不构成架构限制。
建议通过 EasyTier 的协议适配保留普通互通，但不以此否定更优架构；若最终选择破坏
互通，必须列明最低对端版本、受影响拓扑、失败表现及升级方式，不隐含在内部重构中。
下表描述保留普通互通时的接入契约，不承诺旧端支持全部新功能。

| 场景 | 要求 |
|---|---|
| 新节点与旧节点直接连接 | 使用兼容的握手与普通数据通路；新增扩展经过能力确认 |
| 从旧节点读取未宣告属性 | 显式 Unknown；当前严格约束无法证明时不使用该保证 |
| 旧节点作为中继 | 保留普通转发；不能默认它理解新 class、显式路径或连接约束 |
| 向旧终点发送复制数据 | 未确认去重能力时不启用；可由支持节点终止复制段后交付一份 |
| 新节点之间使用扩展 | 扩展有语义版本、能力协商和明确的未知/不支持处理 |
| 严格计划无可用路径 | 报告不可满足或执行策略明确允许的降级，不以“兼容”为由违反契约 |

需要旧节点参与的新功能，必须给出可执行的兼容机制及限制；不能把“保持普通互通”
误写成“所有新策略在旧中继上自动生效”。要求全网一次性升级应被明确列为兼容破坏。

目前可以明确的兼容边界是：内部状态机、属性布局和 API 重写本身不必破坏互通；
若替换旧握手/普通路由承载且不提供适配，将破坏基础互通；新增策略标识、显式路径、
多连接属性承载和复制去重协议若无协商或旧端处理，则会使相应新功能无法跨旧端执行。
具体编码尚未确定，因此这里记录破坏条件，不能提前宣称协议迁移已兼容或已经必然断连。

当前 RawRoutePeerInfo 的原始字节保留只覆盖 RoutePeerInfo；
ConnEdgeAttrs 走解码/重建，而且 build_conn_info 仍可能选择没有属性的 bitmap。
不能宣称任意新增连接属性都已自动跨旧节点透明传播。
协议适配应明确属性承载、未知字段保留、能力协商及多跳丢失时的保守行为。
RouteConnBitmap 可继续服务旧协议，不必决定新内部模型。

逐跳权限投影与属性扩展分开：现有 route_peer_wire 对允许修改的凭据相关字段进行补丁，
不是每增加一个普通属性都需要新写一份补丁逻辑。新承载如何保留原始记录和执行投影，
应在协议适配设计中明确验证。

## 10. 首期实现边界与扩展验收

### 10.1 首期做什么，未来做什么

首期目标是证明框架边界正确，以 GSO/大包路径契约和 #1871 distance 为最小纵向用例。
以下是实现范围建议，不是要求本次文档修改开始实现代码。

| 部分 | 首期最小实现 | 后续扩展 |
|---|---|---|
| 属性 | 单一声明、强类型访问、Unknown、来源与版本 | 更多属性、复杂生成映射与多来源融合 |
| 拓扑 | 有向多连接快照，具体边身份 | 虚拟链路依赖、共享资源/故障域的完整模型 |
| 规则 | 统一类型/谓词/效果机制的最小子集，承载约束与 distance | 完整用户语言、ACL 迁移、QoS 与复杂上下文规则 |
| 求解 | 查询绑定、过滤图、正确的常见加性目标，全量求解 | 自动机、高级多标签、k-best、不相交与集合优化后端 |
| 时间与发布 | 显式输入版本、依赖/过期接口、更新重算与完整快照发布 | 复杂统计、自适应保持、细粒度增量和调度优化 |
| 结果与执行接缝 | 输出一个候选/单发决策及具体连接引用、载荷契约；EasyTier 适配消费 | 引擎扩展分流/复制/主备/分配决策，EasyTier 扩展实际执行和去重 |
| 互通接缝 | 由 EasyTier 保持旧协议适配，输入已协商能力；引擎只宣称可证明的保证 | EasyTier 扩展线上能力及混合网络执行，引擎消费对应属性 |

首期未实现某种执行方式时，可以拒绝该模式；不能先让 GSO 消费者依据一个存在性布尔值
启用无法执行的大包路径。仅有本地属性时，也不能声称已证明未知远端的全路径能力。

### 10.2 如何证明“支持未来扩展”

扩展验收主要验证模型和接口，不提前实现完整产品功能：

- 从空 State 输入拓扑、metric、策略与时间事件，验证结果随输入演化；重放相同输入序列得到一致结果。
- 整个计算测试不创建 socket、不解析 DNS、不启动握手、不接管 EasyTier 生命周期。
- 用同一个核心构造 Node/Tunnel/Flow 属性和两种 profile，验证路由与 ACL 使用同一规则语义。
- 用两份不同时间的观测、同一个 Program，得到不同结果；验证过期能生成重新求值需求。
- 用测试提供者构造两个带边身份与依赖的候选，以及复制计划描述，验证与单发共用结果模型；
  不要求接入真实复制、去重网络。
- 注册一个测试转移/求解扩展，确认上下文、预算与结果精确性可表达，而非修改核心模式分支。
- 使用模拟时钟、连接和能力变化，验证计划失效与发布代次；无需启动真实握手或操作系统 TUN。
- 对仅实现单发的执行器提交复制计划，必须得到明确的不支持，而不是默默只发一份。

“预留扩展”允许后续增加实现和协议，不要求现在设计所有字段，也不承诺内部 API 永不变化。
但不应需要重新定义什么是输入、路由状态、属性、查询、候选、计划和依赖；
与逻辑包和真实连接相关的执行契约由 EasyTier 接入测试验证。

### 10.3 正确性、性能与兼容验证

| 类别 | 验收重点 |
|---|---|
| 最优性 | 随机小图与独立 oracle 比较目标值；平局使用明确的确定性规则 |
| 约束 | 未要求的属性不影响结果；覆盖只有更长路径满足条件、Unknown、源/终点条件与多连接 |
| 算法扩展 | 自动机与接受语义一致；区分简单路径/游走；状态/标签预算超限显式报告 |
| 实际执行 | 使用搜索选中的连接；无效连接不能无条件回退；载荷契约与发送一致 |
| 时间 | 同规则不同观测产生不同结果；窗口过期、权限变化和备用边改善触发相关更新 |
| 发布 | 读者只见完整一代；旧任务不能覆盖新结果；局部更新不使未改条目失效 |
| 旧端互通 | 新旧直连、普通业务、旧中继、属性未知、多跳传播及不支持扩展的处理 |
| 性能 | 分别测规则编译、快照构建、求解、分配、发布、lookup、每包求值与端到端吞吐 |
| 扩展成本 | distance 通过声明、来源/规则和协议适配接入，不增加专用算法与表类型 |

原实现用于回归比较，但旧的漏路、丢属性或不安全执行不是必须保留的行为。
完整旧客户端测试与算法正确性测试各自独立，不能用“新旧下一跳相同”替代二者。

## 11. 当前实现的证据与原讨论的修正

### 11.1 代码现状和已确认的问题

代码检查基线为 42be819c；已有 easytier-attrs 和初步约束路由，因此不再标为“完全未实现”。

| 位置 | 当前行为 | 对目标设计的影响 |
|---|---|---|
| easytier-attrs/src/state.rs | 对固定被跟踪维度一起剪枝 | 只要求 TCP 会被 GSO=false 否决；只要求 GSO 会被混合类型否决 |
| peers/route/peer_ospf_route.rs | least-hop 先建无约束最短子图 | UDP 直达存在时，合格的 TCP 两跳绕行可能提前被删除 |
| easytier-attrs/src/value.rs | 多隧道位集优先折成一个类型 | 丢掉连接身份与其他候选，不能精确绑定发送 |
| peers/conn/peer_map.rs | peer-center 时延按连接聚合 | 与独立类型聚合组合后可能得到不存在的“类型 + 时延” |
| peers/conn/peer.rs | 下一跳内独立选择默认连接 | 搜索约束不自动成为发送保证 |
| peers/route/peer_ospf_route.rs | 约束 lookup 遍历整张 next_hop_map | 数据面应改为目的/查询索引，而非全表扫描 |
| peers/route/graph_algo.rs | 动态属性 map 克隆、复合键哈希、运行时状态截断 | 改为编译状态和紧凑布局，预算超限显式报告 |
| peers/route/route_peer_wire.rs | 原始字节保留有特定承载范围 | 不能泛化为所有连接属性天然透明传播 |
| tunnel/secure_datagram.rs | 固定 256 包重放窗口 | 后续多路径去重与迟到补救需协调窗口 |

相关路径均相对 easytier-core/src，除标明 easytier-attrs 的项目。
本次研究执行的 easytier-attrs 4 个测试与 easytier-core 路由 40 个测试全部通过；
前三类漏路/属性问题由独立最小复现补充验证，尚不等于仓库已有对应回归测试。

### 11.2 性能证据与限制

2026-09-21 的临时合成实验使用预构建全 TCP/GSO 有向图、release 模式、
每组 50 次，比较当前属性搜索、两次原普通 Dijkstra、两次稠密数组 Dijkstra。
两次普通求解覆盖该场景的无约束与合格路径结果，均计算距离和第一跳。

512 节点 / 2,048 条边的一次实验结果：

| 实现 | 平均耗时 | 分配/重分配请求 | 累计申请字节 |
|---|---:|---:|---:|
| 当前属性搜索 | 906 μs | 13,234 | 3,534,248 |
| 两次原 HashMap Dijkstra | 103 μs | 52 | 188,656 |
| 两次稠密数组 Dijkstra | 28 μs | 18 | 40,832 |

耗时与分配计数分开采集；累计字节不是峰值内存。主要可见成本是每条边的属性构造、
路径 BTreeMap 克隆、多份状态键及哈希，甚至无约束搜索也先构造未使用的属性。

这只是定位问题的实验，不是通用策略性能保证或正式跨平台基准；不含建图、同步、
发布和真实收发，不能推导整机吞吐提高同样倍数。正式实现应建立可复现的仓库基准。
它支持“编译后使用紧凑状态/数组”的方向，不支持“通用框架必然慢”的结论。

### 11.3 原 D1–D17 的承接关系

| 原决定 | 本版处理 |
|---|---|
| D1 自动机 | 保留历史约束后端；简单条件编译为过滤；修正正则性是所有可增量求解问题充要条件的说法 |
| D2 函数值 | 保留操作扩展自由；增加算法契约，不禁止有助编译优化的内置操作表示 |
| D3 向量 selector | 保留；全序不足以保证单标签正确，见 §6.3 |
| D4 查询参数与表 | 保留统一结果结构；删除少量候选支持任意 selector 精确 lookup 的承诺 |
| D5 固定 schema | 保留强类型和单一来源；不再排斥生成的稠密计算布局 |
| D6 proto 就是存储 | 单一声明为目标；proto 可作入口或派生承载，消息内 tag 不充当全局身份 |
| D7 组合与观测 | 保留统一扩展框架，区分路径、时间和多来源操作的输入语义 |
| D8 Node/Tunnel/Path | 保留主干，不强制 Channel；增加共享资源关系与流量/查询上下文 |
| D9 方向归属 | 保留单向宣告；增加多连接身份，不以 peer 对单值表示所有隧道 |
| D10 solve/lookup | solve 为内部纯计算；对外采用输入驱动的路由状态机及廉价查询，维护程序、观测、候选与结果依赖 |
| D11 候选与 Allocator | 后续实现；模型同时容纳分流、复制、主备，ECMP 不必依赖 k-best |
| D12 增量后续 | 增量算法可后补，时间依赖和完整快照发布先确定 |
| D13 GSO 与 distance | 保留首期验证用例；GSO 配置不等同能力，distance 保留入向权威 |
| D14 谁写 | 保留来源与权威；多观测者融合是有来源/版本的派生计算 |
| D15 上下文代价 | 保留准入与代价共享充分状态；不把任意历史闭包当作自动满足契约 |
| D16 谓词到效果 | 保留用户规则与生成元数据；补充合并语义及发送/分配效果 |
| D17 统一 profile | 保留一个规则核心；部分求值不等于拆分 ACL/routing 两套规则后端 |

### 11.4 外围功能与技术选型的边界

[#1862](https://github.com/EasyTier/EasyTier/pull/1862) 的 DNS digest、按需获取、
导入/导出规则和配置映射可复用声明与规则机制；zone、DNS 选举、记录解析和各平台
DNS 配置仍是领域实现。Never / Full / Digest 是传播意图，RPC 获取、同步和信任由宿主实现。
此 PR 只作为声明/规则元数据可被上层复用的例子；DNS、zone 和相关生命周期始终在
EasyTier 上层，不属于本路由状态机的现在或未来功能范围。

differential-dataflow 等增量底座可以作为未来技术选型进行对照；首期建议以直接图算法
和依赖驱动更新作为基线。是否引入由真实规模、更新负载、内存、尾延迟和目标平台测量决定，
不沿用“自动免费获得所有增量能力”或未经验证的运行环境绝对限制。

Cedar、CEL、Rego、oso 等可按需作为规则语义或实现对照。选型需验证动作表达、
合并规则、上下文、时间和性能，不因接入现成工具而把 ACL 与 routing 的共同模型拆开。
当前不要求引入这些依赖，也不要求提前实现所有求值 profile。

本文确定的是功能要求与可支持它们的总体边界。声明格式、具体 crate 划分、高级算法、
新协议编码和默认稳定性参数，在对应实现阶段依据这些契约验证和选择。
