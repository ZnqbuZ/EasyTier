## 已有契约回退检查

此次修订保留了以下已通过的边界：

- `manual_routes` 只覆盖 proxy CIDR 来源，不清空其他来源。
- Desired、Observed、Owned、Pending 分离；历史清理台账不自动授权删除当前对象。
- Intent、绑定与 Desired 不能证明创建；Delete 未知结果不能直接重试。
- WAL 的 Intent 持久化先于系统修改，磁盘失败停止新的常规增删改。
- 需求等价性、内核操作冲突与选路冲突分开。
- 完整快照是事实源，通知仅作提示；初次订阅无遗漏，运行中可重新取快照。
- 有界防抖、重试公平性和退出屏障保留。
- 平台确认强度及已验证/待验证范围继续区分。

## 后续步骤的验收承接

以下属于详细设计和实现阶段需要落实的事项，不要求为此继续重写第一步：

1. **第二步：来源协议与版本测试。** 覆盖初始订阅竞态、全量快照乱序/重复、通知丢失后的重同步、撤销后迟到提交、epoch 更替与等待终止。`Revoked` 表示来源退出，不等于系统资源已清理；明确接口返回值和后续清理状态查询的关系。
2. **第三步：结果与归属的类型区分。** `Committed(OpId, ResultProof)` 不能自动等于 Owned。区分创建成功、外部条目满足需求、结果未知和授权接管；用模型测试证明正常、超时、恢复入口采用同一归属门槛。
3. **第四、五步：执行与宿主屏障。** 将实例撤销、迟到操作、清理失败及租约保留落实为可查询的状态。示意图的成功分支不能代替超时/失败处理。委托宿主应实际阻断旧会话配置，并确认屏障成立后再应用新配置。

继续遵守总纲的阶段边界：第二步建立需求接口与来源适配，不启用新的生产系统路由写入者；写入权切换留到第六步。
